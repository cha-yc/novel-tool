# Git 提交信息规范

## 格式要求
提交信息的标题行需为中文，由类型、范围和中文主题组成，可附带正文与页脚，整体格式如下：
<type>(<scope>): <中文标题>

<body>

<footer>

## 标题规范（第一行）
- **type**（必填）：提交类型，只能从以下选项中选择
  - `feat`：新功能
  - `fix`：修复 Bug
  - `docs`：文档变更
  - `style`：代码格式调整（不影响功能，如空格、分号等）
  - `refactor`：重构（既不是新功能也不是修复 Bug）
  - `perf`：性能优化
  - `test`：添加或修改测试
  - `build`：构建系统或外部依赖的变更
  - `ci`：CI/CD 配置变更
  - `chore`：其他杂项变更（不属于以上类型）
  - `revert`：回滚之前的提交

- **scope**（可选）：受影响的模块或范围，使用括号包裹，如 `auth`、`api`、`ui`

- **subject**（必填）：简短描述，不超过 50 个字符，使用中文或英文，无需句号结尾

## 正文规范
- 空一行后开始正文
- 详细说明本次提交的**目的**和**内容**
- 每行不超过 72 个字符
- 可分点列出，清晰易读

## 页脚规范
- 空一行后开始页脚
- 关联 Issue 或任务编号，如 `Closes #123`、`Refs #456`
- 如有破坏性变更，需以 `BREAKING CHANGE:` 开头并说明
